# who-locks

[English](README.md) · **Русский**

`who-locks` называет процессы, у которых открыт файл или каталог. Ему дают папку, которую Windows не даёт переименовать или перенести.

Версия 0.1.0. Это небольшая программа на Zig 0.16 и 0.17. Zig собирает код и под другие системы, поэтому вызовы Windows лежат в одном файле, а остальное это обычный код. Сам поиск написан для Windows. Сборка под другую систему компилируется и останавливается с сообщением.

## Запуск

Нужен [Zig 0.16 или 0.17](https://ziglang.org/download/).

```bash
zig build test
zig build
zig-out/bin/who-locks.exe E:\job\git\pkt-block-topo\.git
zig-out/bin/who-locks.exe --json E:\job\git\pkt-block-topo\.git
```

`zig build run -- <путь>` запускает тот же exe. Если никто не найден, программа завершается с кодом 1, и `zig build run` считает шаг неудачным. Проще запускать exe из `zig-out/bin`.

## Программы и агенты

Программа или агент спрашивает одним абсолютным путём, одним аргументом:

```bash
who-locks --json E:\job\git\pkt-block-topo\.git
```

Один вызов один раз обходит таблицу хендлов и отвечает про этот путь. Второй путь отклоняется. Обход занимает несколько секунд, поэтому спрашивают один раз и пользуются ответом.

stdout это один JSON-объект и перевод строки. stderr несёт ход работы (`scanning open handles...`) и, если проход сорвался, причину. Сначала читают код выхода, потом тело:

| Код | Значение | stdout |
| --- | --- | --- |
| 0 | Найден хотя бы один процесс | JSON, `matched` равен true |
| 1 | Проход завершился, читаемых хендлов нет | JSON, `matched` равен false. Это ответ. |
| 2 | Неверные аргументы или проход не удался | Может быть пустым. Причина в stderr. |

Код 1 легко принять за сбой. Он значит, что проход удался, а `processes` пуст.

```json
{"version":1,"path":"E:\\job\\git\\pkt-block-topo\\.git","matched":true,"handles_seen":620027,"processes":[{"pid":56488,"name":"claude.exe","paths":["E:\\job\\git\\pkt-block-topo\\.git"]}]}
```

`version` равен 1. `matched` равен true, когда `processes` не пуст. `path` это абсолютный путь, с которым сравнивали, без префикса `\?\`. `handles_seen` это сколько хендлов было в таблице. У процесса есть `pid`, `name` (имя файла или `""`, если прочитать не удалось) и `paths` (открытые пути внутри запроса).

Эти имена остаются. Новые поля могут появиться позже. Парсер пропускает поле, которого не знает.

`matched: false` значит, что на путь не указывал ни один читаемый хендл. Защищённый процесс всё ещё может его держать. Код 2 значит, что проход не закончился, и пустой stdout это не ответ.

Текст без `--json` для человека в терминале. `who-locks --help` печатает тот же контракт.

## Пример

Настоящий запуск на этой машине. Claude Desktop держал `E:\job\git\pkt-block-topo\.git`, поэтому папка не переносилась.

```
scanning open handles...
E:\job\git\pkt-block-topo\.git

56488  claude.exe
  E:\job\git\pkt-block-topo\.git

looked at 614074 handles
```

Строка `scanning open handles...` идёт в stderr, так что `--json` в stdout остаётся одним объектом. who-locks печатает, кто держит. Закройте эту программу, и каталог можно переносить.

## Что считается совпадением

Путь совпадает сам с собой и со всем, что внутри. Регистр латиницы не важен, регистр русских букв (А–Я и Ё) тоже.

`E:\work` совпадает с `E:\work\.git\index`. `E:\workspace` это другой путь. Корень диска, например `E:\`, совпадает со всем диском. Завершающий слэш не важен. Префикс `\?\`, который Windows добавляет к некоторым путям, перед сравнением убирается.

Каталог считается открытым, когда процесс держит сам каталог или файл внутри. В этой ситуации переименование или перенос не удаются.

## Как это устроено

Поиск идёт в обычном пользовательском режиме. Драйвера в программе нет.

Она запрашивает у Windows системную таблицу хендлов, дублирует те, которые ей разрешено видеть, и читает путь, если хендл указывает на файл или каталог. Таблица берётся через `NtQuerySystemInformation`, класс 64 (`SystemExtendedHandleInformation`). Это не документированная функция Win32. Handle из Sysinternals читает такую же таблицу. Путь даёт `GetFinalPathNameByHandle`.

Драйвер понадобился бы, чтобы принудительно закрыть чужой хендл или заглянуть в защищённый процесс. who-locks этого не делает. Он показывает то, что и так видно из пользовательского режима.

На этой машине в таблице около 600 тысяч хендлов, проход занимает несколько секунд.

## Что проверено

| Где | Что вышло |
| --- | --- |
| Windows 11 Pro, сборка 22631, x86_64, Zig 0.16.0 | Пример выше. |
| Windows 11 Pro, сборка 22631, x86_64, Zig 0.17.0 | `zig build test` проходит, проход `--json` выполняется. Исходники программы те же. `build.zig` передаёт `zig build run -- <путь>` через `Build.args` на 0.16 и через `addPassthruArgs` на 0.17. |
| Linux, цель `x86_64-linux-musl` | `zig build -Dtarget=x86_64-linux-musl` компилируется. На Linux бинарник не запускался. Сканера в нём нет. |
| macOS, цель `x86_64-macos` | `zig build -Dtarget=x86_64-macos` компилируется. На Mac бинарник не запускался. Сканера в нём нет. |

Windows 10 не проверялась. Раскладка таблицы хендлов не документирована, поэтому будущая Windows может сломать проход. Тогда программа завершится с ошибкой и не выдумает владельца.

## Ограничения

- Таблица хендлов разбирается для 64-битной Windows.
- Процессы того же пользователя видны из обычного терминала. Процессы других пользователей и многие службы видны из терминала, запущенного от администратора.
- Защищённые процессы, например часть служб антивируса, могут не дать себя открыть. Они остаются невидимыми и в терминале администратора. Пустой результат всё ещё оставляет такую возможность, и непустой результат может такой процесс пропустить.
- Регистр сворачивается для латиницы и русской кириллицы. Остальные алфавиты сравниваются как написаны.
- Хендл, открытый через GUID тома (`\\?\Volume{...}\`), можно пропустить, если введённый путь идёт через букву диска.
- Программа перечисляет тех, кто держит путь. Закрывать хендл она не станет.

## Код выхода

| Код | Значение |
| --- | --- |
| 0 | Найден хотя бы один процесс |
| 1 | Ни один читаемый хендл не совпал |
| 2 | Неверные аргументы или проход не удался |

Те же три кода действуют и для текста, и для `--json`. Поля описаны в разделе [Программы и агенты](#программы-и-агенты).
